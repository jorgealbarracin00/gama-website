Authoritative direction • 8 October 2026 • Website deployment approved by user: “deploy”

## Identity
Every Item. Every Stage. Every Second. Experimental industrial flow concept with an existing deterministic iPad demonstration inside GAMA DEMO. Public product not verified; browser simulation and futuristic interfaces explicitly conceptual.

## Existing prototype
Six stages: Picking, Racking, Washing, Coating, De-racking, Finishing; PRE / ACTIVE / POST / outside zones; tracked T-number trolleys, fixtures, units, timestamped operator events, returns and completions. Setup allows stage edits, while core scripted history remains scenario-based. Live choreography, individual journeys, replay controls, insights and fixture daily report. Report values are authored sample data, not measured performance. Width below 780 displays an iPad landscape notice. Future web model is a new coherent simulation, not a port of those scripted fixtures.

## Simulation contract
Eight sequential stages: Preparation, Cleaning, Racking, Pre-coating waiting, PVD coating, Post-coating waiting, Unloading and inspection, Assembly and completion. Six active stations, two timed buffers; buffers add minimum dwell plus queue time. FIFO per-stage queues; no item duplication or identity changes. Each process configurable service duration and capacity. Arrivals: 24 items at 12 simulated-second intervals (deliberately illustrative, not real PVD timings). Base model allows smooth finite flow. Bottleneck slows a selected process 5x and reduces effective capacity to one; already active work completes under its start-time service contract. Restore affects subsequent admissions; no queue deletion. Finite arrivals allow natural clearance. Capacity reductions do not evict work already in progress.

Clock uses deterministic discrete events. No animation position drives data. Time accelerators 1/5/20/100, start/pause, reset, selected item full history, selected station elapsed/expected service, queue position/length/average wait/capacity, manager mode. Thresholds configure attention/delayed/critical in ascending simulated seconds. Active + waiting = elapsed journey for each arrived item. Flow efficiency = sum active / sum journey × 100; includes work in progress and labels that population explicitly. Throughput completed items / elapsed hours. Reduced motion disables transitions; start is user-controlled; pause and step remain available. Hidden tab pauses. Tests verify conservation, partition, FIFO, capacity, chunk independence, bottleneck build and natural clearance, buffer classification and final completion.
